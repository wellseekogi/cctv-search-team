# MEVA 영상 검색 통합 평가

평가 영상 2개의 전체 시간대를 검색했을 때, 한국어와 영어 모두 12문항 중 6문항에서 상위 5개 안에 정답 장면이 있었다. 한국어에서는 사람의 외형을 묻는 질의 3/4, 사건을 묻는 질의 3/8이 적중했다. 첫 결과만 보면 전체 2/12였다.

## 전체 영상에서 정답 시간 찾기

개발용 G340·G341·G421·G506과 평가용 G299(체육관)·G638(광장)을 분리했다. 각 원본은 약 5분, 30fps다. 전체 시간대에서 4초 간격으로 후보를 만들고 F의 참조 이미지 제외 구간 10개를 적용했다. 개발 후보는 298장, 평가 후보는 149장이다. 한국어와 영어는 같은 사건의 번역 쌍이다.

| 갤러리와 질의 | 1위 | 상위 3개 | 상위 5개 |
|---|---:|---:|---:|
| 평가 · 한국어 텍스트 | 2/12 | 5/12 | 6/12 |
| 평가 · 영어 텍스트 | 2/12 | 5/12 | 6/12 |
| 평가 · 참조 이미지 | 2/5 | 4/5 | 4/5 |
| 개발 · 한국어 / 영어 | 0/15 · 1/15 | 2/15 · 3/15 | 4/15 · 4/15 |
| 개발 · 참조 이미지 | 0/5 | 1/5 | 1/5 |

적중 조건은 반환 프레임이 정답 영상의 지정 시간 구간에 드는 것이다. SigLIP2 텍스트 검색은 전체 화면 점수와 네 모서리 부분 화면 중 최고 점수의 평균을 쓴다. 같은 후보에서 전체 화면만 썼을 때 평가 Top 5는 두 언어 모두 4/12였다. 부분 화면을 더해 각 2문항이 늘었다. 이미지 질의는 전체 화면 코사인 점수로 정렬했다.

한국어에서 회색 티셔츠·검은 모자의 자전거 이용자는 1위, 자전거를 건네는 장면은 3위였다. 테이블 옆 통화는 24위, 체육관의 포옹은 44위였다. 이미지 질의 5개 중 4개가 적중했지만 개발 영상에서는 1/5였다. 평가 텍스트 한 문항이 8.3%p, 이미지 한 문항이 20%p를 차지한다.

## 질의의 어떤 조건을 구분하는가

F가 분류한 평가용 외형 질의는 한국어·영어 모두 3/4(75%), 사건 질의는 모두 3/8(37.5%)이었다. 외형 4문항 중 3개가 자전거 이용자를 묻는다. 이 차이에는 복장뿐 아니라 자전거와 배경 단서도 포함된다.

두 장 중 질문에 더 맞는 장면을 고르는 보조 실험에서는 6대 영상에서 미리 정해 둔 53쌍을 양 언어로 다시 채점했다. 정답 프레임의 점수가 비교 프레임보다 0.000001을 초과해 높으면 적중이다. 장소 질문은 다른 카메라끼리, 나머지는 같은 카메라 안에서 비교했다.

| 두 장 중 구분할 조건 | 한국어 | 영어 |
|---|---:|---:|
| 장소와 배경 | 4/4 | 4/4 |
| 사물 하나 | 4/5 | 5/5 |
| 두 대상이 함께 보임 | 4/4 | 4/4 |
| 옷차림 한 가지 | 4/7 | 6/7 |
| 옷차림 두 가지 | 3/4 | 3/4 |
| 대상 간 거리 | 3/7 | 5/7 |
| 화면 기준 좌우 | 4/8 | 4/8 |
| 앉기와 옆에 서기 | 2/4 | 2/4 |
| 문 열림 등 사물 상태 | 1/4 | 2/4 |
| 한 프레임에 보이는 행동 | 3/6 | 3/6 |

장소와 큰 사물은 이 비교에서 잘 구분했다. 좌우를 바꿔 물은 4쌍에서는 두 언어 모두 같은 프레임을 양쪽 질문에서 선호했다. 좌우 4/8은 방향을 구별하는 증거로 쓰기 어렵다. 수동 선정한 두 후보의 우연 적중 기준은 50%이며 일부 프레임을 여러 번 사용했다. 이 표를 전체 CCTV 검색 정확도로 환산할 수 없다.

## A 제출본과 실제 인물 추적 성능

A의 보완 커밋 2880474가 제공한 6개 manifest에서 B 영상 ID와 원본 SHA-256을 읽고, F manifest에서 실제 영상 길이·경로·분할을 가져왔다. 6개 원본 파일의 해시가 일치했다. B가 실제 추적한 카메라별 첫 10초(0~9.8초, 200ms 간격 50프레임)로 A의 이벤트·혼합·고정 1초·2초·5초 정책을 다시 실행했다. 30개 샘플 파일이 이전 동일 입력 실행과 바이트 단위로 일치했다.

어제 시험한 1초 간격 인물 보충 규칙은 A 원본 정책에 없어서 통합 기본값과 아래 평가에서 제외했다. 정답 주석을 사용한 카페 데모도 제외했다. 평가 2대의 A 혼합 정책 결과 71개가 C 인덱스와 항목별로 일치했다. D 제출본 923d555의 API에 실제 SigLIP2와 B 관측 638개·24개 트랙을 연결하고 결합 순위로 검색했다.

| D 인물 추적 API · 상위 5개 | 정답 시간 후보가 있는 질의 | 영상과 시간 적중 | 시간과 사람 박스 적중 |
|---|---:|---:|---:|
| 한국어 텍스트 | 4/12 | 4/12 | 3/12 |
| 영어 텍스트 | 4/12 | 4/12 | 3/12 |
| 참조 이미지 | 1/5 | 1/5 | 1/5 |

반환된 트랙의 대표 프레임을 채점했다. 박스 적중은 같은 프레임에서 해당 정답 인물과의 IoU(겹친 면적 ÷ 합친 면적)가 0.5 이상일 때다. 시간 후보가 있는 텍스트 4건에 한정하면 사람 적중은 두 언어 각각 3/4다. 테이블 옆 통화는 한국어에서 정답 시간이 3위였지만 그 사람의 박스는 상위 5개에 없었다.

텍스트 24회와 이미지 5회 모두 D API에서 HTTP 200을 받았다. 전체 약 5분의 인물 추적 정확도, 다른 카메라에서의 일반화, 대화 답변의 정확도는 이 수치로 판단할 수 없다. B 완료 로그가 없어 A 실행 상태는 부분 관측으로 유지했다. 11월 20일 별도 웹 시험에서는 없는 장면에도 15/15회 후보를 반환했고 직전 2위 항목을 다시 묻는 질문에서 0/15회 같은 항목을 유지했다.

## 근거와 재현

[질의별 순위와 두 프레임 점수 차이](results.json) · [A 원자료와 30개 비교 해시](a-verification.json) · [보조 실험 문항](pairs.txt) · [이전 웹 대화 시험](../2026-11-20-meva/README.md) · [원본 출처·라이선스](../../../data/meva/data_inventory.csv)

Python 3.11 환경에서 프로젝트의 `requirements-live.txt`와 `requirements-d.txt`를 설치한다. 원본과 B 관측은 별도 인계 자료이며 저장소에서 사용하는 상대 경로는 아래 예시와 같다. 평가 hybrid 인덱스는 아래 A 샘플을 G299, G638 순서로 합쳐 `python -m team_search build`로 생성하거나 같은 샘플로 만든 C 인덱스를 사용한다. 장면 인덱스에는 F 제외 구간을 적용한 4초 간격 전체 프레임과 `python -m tools.encode_scene_views --index <인덱스>`의 네 영역 벡터가 필요하다. 평가 박스는 원본 목록의 KPF 리비전 f844579a에서 G299.geom.yml과 G638.geom.yml로 준비한다.

```powershell
python tools/prepare_bf_v10.py --b-inputs runs/meva-public/first-50/b-inputs --b-manifests metadata/baseline_T3 --f-data data/meva --out runs/final-a
Get-Content runs/final-a/inputs/G299/tracks.jsonl,runs/final-a/inputs/G638/tracks.jsonl -Encoding utf8 | Set-Content runs/final-a/eval-tracks.jsonl -Encoding utf8NoBOM
python -m retrieval check --config configs/retrieval.meva-eval.yaml
python -m api --config configs/retrieval.meva-eval.yaml
```

별도 터미널에서 다음 명령으로 검증한다. 평가기는 D API를 프로세스 안에서 직접 호출한다. F의 공식 PNG가 있으면 `--images <PNG 폴더>`를 추가한다. 생략하면 OpenCV로 F가 지정한 원본 프레임과 crop_box에서 PNG를 만들고 SHA-256을 검증한다. 이 방식은 `opencv-python`이 필요하다.

```powershell
python -m evaluation.benchmark_integrated_meva --config configs/retrieval.meva-eval.yaml --dev-scenes runs/accuracy-loop/region-store/indexes/meva-regions-dev/index --eval-scenes runs/accuracy-loop/meva-regions-eval/index --geometry runs/search-audit --pairs evaluation/reports/2026-11-21-meva/pairs.txt --output runs/result-check.json
python -m pytest -q tests evaluation/tests
```
