# 프레임 상태로 MEVA 사건을 더 잘 찾는가

**기존 전체 B→A를 프레임 상태 검색으로 교체하면, 사건 Top 5는 한국어 3/8→2/8, 영어 4/8→3/8로 각각 12.5%p 하락했다.** 반면 양쪽을 카메라당 40개 시점으로 제한하면 기존은 두 언어 모두 1/8이어서 상태 방식이 한국어 1문항, 영어 2문항 앞섰다. 이 결과가 지지하는 용도는 검색 후보를 소수로 줄여야 할 때 구간을 고르는 것이다. 행동을 자동 판정하는 A로 대체할 근거는 부족하다.

| 검색 경로 | 한국어 사건 Top 5 | 영어 사건 Top 5 | 한국어 전체 Top 5 | 영어 전체 Top 5 |
|---|---:|---:|---:|---:|
| 기존 B→A 전체 1,680시점 | 3/8 (37.5%) | 4/8 (50.0%) | 5/12 | 6/12 |
| 기존 B→A에서 80시점 선택 | 1/8 (12.5%) | 1/8 (12.5%) | 3/12 | 4/12 |
| 균일 80구간 + 3프레임 검색 | 3/8 (37.5%) | 2/8 (25.0%) | 5/12 | 4/12 |
| 상태 80구간 + 3프레임 검색 | 2/8 (25.0%) | 3/8 (37.5%) | 4/12 | 5/12 |

**어떤 결과가 바뀌었나.** 한국어 ‘관람석에서 문자 보내기’는 기존 68위에서 상태 방식 2위로 올랐다. 반면 ‘자전거 건네기’는 4위에서 9위, ‘낮은 담에 앉아 휴대전화 보기’는 2위에서 23위로 밀렸다. 영어도 문자 보내기를 새로 찾았지만 테이블 옆 통화와 낮은 담의 휴대전화 장면이 Top 5에서 빠졌다. 두 언어 모두 한 문항을 얻고 두 문항을 잃었다.

**적용 판단.** 현재 전체 검색은 유지하고 프레임 상태는 브랜치의 `events` 명령으로 분리했다. 다음에 검증할 변경은 후보를 더 많이 생성하는 것보다 **같은 인물·장소에서 반대 행동을 구분하는 판정기**다. 짧은 고정 구간을 사건의 전체 길이로 연결하는지도 별도로 측정해야 한다.

## 어떤 문제를 시험했나

기존 A의 `object_event`는 사람 트랙의 시작, 재등장, 위치 이동, 관측 품질 향상 등을 기록한다. 코드에도 `event_semantics="sampling_trigger_not_action_label"`가 명시돼 있다. 기본 `hybrid`가 5초 주기의 장면도 추가하므로 B가 사람을 놓친 시간도 일부 검색할 수 있다. 다만 자전거를 타는지 건네는지 판별하는 학습 목표는 이 경로에 없다. [기존 A 로직](../../../sampling/core.py) · [기존 A 설정](../../../configs/person/hybrid.yaml)

새 경로는 **사람 박스 없이 어떤 구간을 다시 볼지 선택하면 실제 행동 검색이 개선되는가**를 시험한다. 원본을 초당 한 번 128×96 명암 영상으로 읽고 8×6 타일에서 직전 상태와의 변화, 장기 배경과의 편차를 계산한다. 화면 전체의 밝기 이동은 중앙값으로 보정한다. 변화가 큰 국소 영역과 전역 신호를 이용해 약 4초 구간을 고르고, 예산의 일부는 주기적인 확인에 사용한다. 행동 클래스나 질의 정답은 후보를 만들 때 사용하지 않는다.

검색에는 시작·중앙·끝 프레임의 전체 화면과 활동 영역을 기존 SigLIP2로 임베딩하고 질의와의 여섯 유사도를 평균했다. 이 평균은 순서가 바뀌어도 같다. 시간 순서가 실제로 도움이 되는지는 별도로 X-CLIP에 같은 구간의 **8프레임을 정순, 역순, 가운데 한 장 반복**으로 제공해 시험했다. X-CLIP에는 영어 원문과 전체 화면을 사용했다. 이 실험은 첨부 제안 중 비학습 상태 신호와 영상·텍스트 판정을 검증한 범위다. 학습형 경계 검출, 구간 병합, 상시 임베딩 보조 색인, 비디오 언어 모델의 자유 캡션은 평가 범위 밖이다. [후보 생성 코드](../../../sampling/frame_state.py) · [구간 검색](../../../team_search/frame_state.py) · [X-CLIP 모델 카드](https://huggingface.co/microsoft/xclip-base-patch32)

## 같은 영상과 질의로 비교한 방법

| 조건 | 입력과 평가 단위 |
|---|---|
| 영상 | 보류한 MEVA G299 체육관 300.333초, G638 광장 300.033초. 두 카메라를 하나의 검색 대상으로 사용 |
| 질의 | F의 사건 8개, 외형 4개. 영어 원문과 한국어 번역을 각각 평가. 두 언어는 같은 12문항 |
| 기존 방식 | 기준 커밋 `82b4e45`의 Lite-DETR·ByteTrack B를 200ms 간격으로 전체 재실행한 뒤 A hybrid, C SigLIP2, 기존 전체 검색의 순위 계산을 사용 |
| 대조군 | 카메라별 40개씩 총 80개. 균일 후보와 상태 후보에 동일한 구간 길이, 제외 규칙, 활동 영역 추출, 임베딩 480회, 질의를 사용 |

**주 지표는 Top 5 시간 적중률**이다. 상위 5개 중 하나의 대표 프레임이 F의 정답 영상과 반열린 정답 시간 구간 안에 있으면 한 문항 적중이다. 기존 검색은 대표 프레임 시각, 새 검색은 중앙 증거 프레임 시각을 사용했다. 기존 B→A와의 비교는 전체 파이프라인 교체 효과다. 후보 선택만의 효과는 동일 예산의 균일 대조군으로 판단한다. F의 참조 이미지 보호 구간은 기존 방식에서 프레임을, 구간 방식에서 겹치는 창 전체를 제외했다.

기존 B는 3,003프레임을 관측했고, A는 장면 999개·사람 크롭 3,100개를 선택했다. C에서 4,099개 항목을 임베딩하고, 같은 프레임의 항목을 합친 **1,680개 시점**을 검색했다. 상태 방식은 **80개 시점에 480개 이미지 임베딩**을 사용했다. 검색 가능한 시점 수의 영향을 보기 위해 기존 1,680개 시점에서도 카메라별 시간순 분위수 중점 40개만 남긴 대조군을 만들었다. 이 80개 시점에는 원래 장면·크롭 182개가 속한다. 이 대조군도 기존 B의 검출·추적 연산은 모두 수행했다.

**기존 검색 후보에도 사건 8개 전부의 정답 시간이 이미 들어 있었다.** 전체 질의로도 기존은 12/12, 상태는 11/12였다. 따라서 이 영상에서 기존 검색이 어떤 사건을 Top 5에서 놓쳤다면, 적어도 정답 시간의 부재로 설명할 수는 없다. 남는 문제는 그 시간의 이미지·크롭이 행동의 증거를 담았는지, 질의가 그 증거를 높은 순위로 끌어올렸는지다.

사람이 주석한 활동 576개로 후보의 **시간 IoU(tIoU)**도 측정했다. tIoU는 두 구간이 겹친 시간을 합집합 시간으로 나눈 값이다. 한 활동에 대해 임계값을 넘는 같은 카메라 후보가 하나라도 있으면 회수한 것으로 센다. 이는 행동 이름, 대상 인물, 검색 순위를 요구하지 않는 후보 지표다. 질의 기준의 엄격한 구간 적중과도 분모가 다르다.

F의 평가 텍스트 질의가 참조하는 양성 30행은 모두 인물 트랙 ID를 사용한다. 원본 주석을 대조하면 30행 모두 해당 인물이 참여한 같은 카메라 활동의 시작·종료와 정확히 일치한다. 예를 들어 자전거 전달 두 참여자는 103.233~105.900초, 체육관 포옹 두 참여자는 117.967~122.333초다. 같은 시각에 다른 사람이 화면에 있어도 시간 적중으로 계산한다.

보류 분할은 팀이 기존 보고서에서 이미 사용한 두 카메라다. 이번 실험은 분당 8개의 후보 예산과 두 언어에 같은 점수식을 정해 비교했다. 사건 질의 한 개가 12.5%p이고, 두 카메라 중 체육관이 활동 주석 576개의 529개를 차지한다. 배포 정확도나 다른 CCTV에서의 평균 효과로 일반화하기에는 표본이 작다.

## 후보를 더 잘 골랐나

| 사람 주석 576개 중 회수 | 균일 후보 80개 | 상태 후보 80개 |
|---|---:|---:|
| 조금이라도 시간 겹침 | 478 (83.0%) | 355 (61.6%) |
| tIoU ≥ 0.3 | 204 (35.4%) | 159 (27.6%) |
| tIoU ≥ 0.5 | 81 (14.1%) | 77 (13.4%) |
| tIoU ≥ 0.7 | 26 (4.5%) | 25 (4.3%) |

**상태 후보가 자주 움직이는 시간에 몰렸다.** 중복을 합친 영상 시간은 균일 선택 320.0초, 상태 선택 246.0초였다. tIoU 0.5에서 체육관은 74/529에서 73/529로, 광장은 7/47에서 4/47로 바뀌었다. 두 카메라의 상태 후보 80개 중 변화 우선 54개, 주기적 확인 26개였다. 지속 상태 신호가 별도 후보 사유로 선택된 구간은 없었다.

**반면 실제 질의가 가리키는 시간의 일부는 새로 확보했다.** 순위에 관계없이 중심 프레임이 정답인 질의는 균일 10/12와 상태 11/12였다. 광장의 자전거 전달은 상태 후보가 잡았고, 체육관 문 닫기는 둘 다 놓쳤다. 상태 후보 중 자전거 전달은 3프레임 검색에서 영어 3위, 한국어 9위였다. 후보를 만들었어도 질의 언어와 의미 순위에 따라 사용자에게 보이는 결과가 달라졌다.

**세 장을 평균하면서 사라진 단서도 있었다.** 동일한 상태 후보에서 가운데 한 장의 전역·지역 점수만 사용하면 사건 Top 5는 한국어·영어 모두 3/8이었다. 세 시점을 평균하면 한국어는 2/8, 영어는 3/8이 됐다. 한국어 자전거 전달이 4위에서 9위로 밀렸다. 한순간 드러나는 단서를 평균이 희석할 수 있다는 사례다.

**4초 구간은 긴 상태의 경계를 표현하기 어렵다.** tIoU 0.5가 가능하려면 2~4초 후보와 짝지을 정답 길이가 1~8초 안에 있어야 한다. 실제 질의 중 이 필요조건을 만족하는 문항은 전체 5/12, 사건 3/8이었다. 정답 중간을 반환해 시간 적중에 성공해도 긴 통화 전체의 시작·종료는 틀릴 수 있다.

## 행동 방향을 구분했나

같은 80개 후보에서 8프레임 영상 모델의 영어 사건 Top 5는 **정순 3/8, 역순 3/8, 가운데 한 장 반복 4/8**이었다. 원래 순서에서 적중한 사건은 관람석 통화, 테이블 옆 통화, 관람석 문자였다. 세 조건 모두 사건 질의 Top 5에서 tIoU 0.5로 구간까지 맞힌 사례는 0/8이었다.

같은 장면에 대해 반대 방향의 두 영어 문장 중 어떤 쪽의 점수가 높은지도 확인했다. 중심 시각에 두 행동 중 하나만 주석된 경우를 사용했다. 균형 정확도는 두 행동의 정답률을 각각 구해 평균한 값이다.

| 행동 쌍 | 중심 시각의 표본 | 정순 균형 정확도 | 가운데 한 장 반복 |
|---|---:|---:|---:|
| 물건 집어 들기 / 내려놓기 | 7 / 8 | 50.0% | 50.0% |
| 앉기 / 일어서기 | 5 / 1 | 10.0% | 10.0% |
| 출입구를 통해 화면에 등장 / 퇴장 | 4 / 7 | 35.7% | 28.6% |
| 시설 문 열기 / 닫기 | 0 / 0 | 측정 불가 | 측정 불가 |

집어 들기·내려놓기에서는 모델이 15개 전부를 내려놓기로 골랐다. 두 동작이 동시에 주석된 후보 5개는 제외했다. 다른 인물이나 활동은 같은 프레임에 있을 수 있어 이 결과는 전체 화면을 본 모델의 행동 구분 능력을 평가한다. 대상 인물을 특정하는 능력은 이 평가로 측정하지 않았다.

## 실행 및 근거

아래 명령은 저장소 루트에서 실행한다. 일반 검색은 첫 명령이다. X-CLIP 옵션은 공식 `microsoft/xclip-base-patch32` 리비전 `a2e27a78a2b5d802e894b8a1ef14f3a8ce490963`의 모델 폴더를 사용한다. 코드가 가중치 SHA-256을 확인한다. 기존 B 모형·원본 준비 방법은 저장소의 전체 검색 안내를 따른다.

```powershell
.\run-search.cmd events --dataset meva --split eval --question "벽돌 광장에서 자전거를 건네는 장면"
.\run-search.cmd events --dataset meva --split eval --video-model runs/frame-state/xclip-base-patch32 --question "a man handing his bicycle to another person on a brick plaza"
python -m evaluation.frame_state_baseline --device cpu --b-device cuda --output runs/state-baseline/full-results.json
python -m evaluation.benchmark_frame_state --split eval --policy uniform
python -m evaluation.benchmark_frame_state --split eval --policy state
python -m team_search.state_verifier --windows runs/frame-state/eval-state-windows.jsonl --manifest data/meva/manifest.jsonl --media runs/source-data --queries data/meva/queries.jsonl --action-targets data/meva/targets.jsonl --model runs/frame-state/xclip-base-patch32 --device cuda --out runs/frame-state/xclip-scores-action-pairs.json
python -m evaluation.compare_frame_state --output runs/frame-state/paired-results.json
python -m pytest -q tests evaluation/tests
```
