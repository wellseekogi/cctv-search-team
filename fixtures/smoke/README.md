# fixtures/smoke — 평가 입력 형식 예제

`data/virat/`에서 영상 1개(`VIRAT_S_040103_03_000284_000425`, dev)만 잘라 낸 작은 예제입니다. 전체 데이터 없이 파일 형식을 확인하거나 평가 코드를 빠르게 시험할 때 씁니다. 형식은 실제 데이터와 같습니다(`cctv-3.0`).

| 파일 | 행 | 내용 |
|---|---|---|
| `manifest.jsonl` | 1 | 영상 정보 |
| `tracks_gt.jsonl` | 1,272 | GT 트랙 11개의 전체 관측 |
| `targets.jsonl` | 11 | 평가 대상 |
| `queries.jsonl` | 2 | `vq_d04` a little girl in a pink outfit / `vq_d05` a man pulling a green cart |
| `qrels.jsonl` | 4 | vq_d04 정답 3개(g006·g016·g005), vq_d05 정답 1개(g014) |
| `predictions.jsonl` | 2 | D 출력 형식의 검색 결과 예제 (질의별 순위·track_uid·score) |
| `expected_metrics.json` | – | 위 예측으로 손계산한 기대 지표 |

트랙 11개는 세 종류입니다.
- **정답 트랙 4개:** vq_d04의 g005·g006·g016, vq_d05의 g014
- **방해 트랙 6개:** 평가 가능한 사람 트랙 g000·g001·g002·g003·g007·g043
  - g001·g043은 2차 검수(2026-11-19)에서 vq_d04 정답에서 빠졌습니다.
- **지원하지 않는 클래스 1개:** car 트랙 g015. `evaluable=false`이고 `na_reason=unsupported_class`입니다.

vq_d05의 원래 정답이던 car 트랙(g031)은 사람만 탐지 기준에 따라 qrels에서 뺐습니다(`data/virat/excluded_queries.jsonl`).

## 기대 수치 (손계산)
지표 정의는 평가 코드와 같습니다.
- Recall@K: 질의별로 상위 K 안의 정답 트랙 수를 그 질의의 정답 트랙 수로 나누고, 질의들의 평균을 냅니다.
- MRR: 질의별 첫 정답 순위의 역수를 평균합니다. 순위에 정답이 없으면 0입니다.

| 질의 | 정답 순위 | Recall@5 | Recall@10 | RR |
|---|---|---|---|---|
| vq_d04 (정답 3) | g006 **1위**, g016 **4위**, g005 **미검색** | 2/3 | 2/3 | 1/1 = 1 |
| vq_d05 (정답 1) | g014 **8위** | 0/1 | 1/1 | 1/8 = 0.125 |
| **전체 (2개 평균)** | | (2/3 + 0)/2 = **0.3333** | (2/3 + 1)/2 = **0.8333** | (1 + 0.125)/2 = **0.5625** |

명세의 예시는 질의 3개가 각각 1위·4위·미검색인 경우입니다(Recall@5 = 2/3, MRR = (1 + 1/4 + 0)/3 = 0.4167). smoke는 질의가 2개라 구성이 다릅니다.
- vq_d04 한 질의 안에 1위·4위·미검색을 넣었습니다. 그래서 이 질의의 Recall@5가 명세와 같은 2/3입니다.
- vq_d05는 정답이 상위 5 밖(8위)에 있는 경우입니다. Recall@5와 Recall@10이 갈리는 것을 보여 줍니다.

F의 `evaluation/metrics.py`(`evaluate_rankings`)로 계산한 값과 같습니다. recall@5 0.3333, recall@10 0.8333, mrr 0.5625입니다.
